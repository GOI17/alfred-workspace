The `alfred` CLI talks to a running Alfred runtime. Use it when a shell script or agent needs to inspect worktrees, launch terminals, open files, automate the built-in browser, or report progress back into Alfred.

## Verify the runtime

Register the CLI under [Settings → General → Alfred CLI](/docs/settings), then check that it can reach Alfred.

<Callout title="On Linux the command is alfred-ide">
  GNOME Alfred — the screen reader that ships with most GNOME desktops — already owns
  `/usr/bin/alfred`, so Alfred's Linux CLI installs as `alfred-ide`. Do not check for it with
  `command -v alfred`: that succeeds on a GNOME desktop and resolves to the screen reader, not to
  Alfred. This page writes `alfred` throughout — read it as `alfred-ide` on Linux. See [Install →
  Linux](/docs/install#linux).
</Callout>

On macOS and Windows:

```bash
command -v alfred
alfred status --json
```

On Linux:

```bash
command -v alfred-ide
alfred-ide status --json
```

If Alfred is not already running:

```bash
alfred open --json
alfred status --json
```

Use `--json` when another tool will parse the result. Human-readable output is for quick terminal checks.

## Selectors

Most commands accept selectors instead of requiring long IDs:

```bash
alfred repo show --repo id:<repoId> --json
alfred worktree show --worktree active --json
alfred worktree show --worktree path:/abs/path/to/worktree --json
alfred worktree show --worktree branch:feature-name --json
alfred worktree show --worktree issue:123 --json
```

`active` and `current` resolve to the enclosing Alfred-managed worktree from the shell's current directory or terminal context. Use explicit selectors in scripts that may run outside the target worktree. For remote runtimes, prefer full server-side selectors such as `id:<repoId>::<absolute-worktree-path>` or `path:<absolute-server-path>` because the local shell's current directory may not exist on the runtime host.

## Choose a host

List every machine the current Alfred host can target and the selector for each one:

```bash
alfred host list --json
```

The result includes this machine, its registered [SSH targets](/docs/ssh), and paired [Remote Alfred Servers](/docs/remote-servers). Use `--host local` for this machine, `--host ssh:<target-id>` for an SSH target, and `--environment <server-name>` for a paired server. SSH rows include the detected remote platform (`linux`, `darwin`, or `win32`) after the target connects; older or disconnected targets report `platform unknown`. They also include `connected` and, when known, the SSH lifecycle `connectionStatus`. SSH labels and paired-server names also resolve when they are unique; use the IDs from `host list` when names collide. If you put a machine name on the wrong selector, Alfred reports the matching machine and the flag to use instead of returning an empty result.

## Runtime commands

```bash
alfred open --json
alfred status --json
alfred serve --port 6768 --pairing-address 100.64.1.20 --json
```

`alfred serve` starts a runtime server in the foreground without opening the desktop window. Use it for [Remote Alfred Servers](/docs/remote-servers) or headless environments, and stop it with `Ctrl-C`.

## Repos

```bash
alfred repo list --json
alfred repo add --path /abs/path/to/repo --json
alfred repo show --repo id:<repoId> --json
alfred repo set-base-ref --repo id:<repoId> --ref origin/main --json
alfred repo search-refs --repo id:<repoId> --query main --limit 10 --json
```

Set the repo base ref before creating lots of worktrees so new tasks branch from the right place by default.

## Worktrees

```bash
alfred worktree list --repo id:<repoId> --json
alfred worktree ps --json
alfred worktree current --json
alfred worktree show --worktree active --json
alfred worktree create --repo id:<repoId> --name fix-login --json
alfred worktree create --name child-task --agent codex --prompt "Investigate the flaky login test" --json
alfred worktree set --worktree active --comment "reproduced failure; testing token refresh fix" --json
alfred worktree rm --worktree id:<worktreeId> --force --json
```

When `worktree create` runs from inside an Alfred-managed worktree, Alfred records the new worktree as a child when it can infer the relationship. Pass `--parent-worktree active` to be explicit, or `--no-parent` when the new work is independent.

Agent startup flags:

```bash
alfred worktree create --name review-api --agent claude --setup run --json
alfred worktree create --name quick-check --agent codex --prompt "Summarize the diff" --setup skip --json
alfred worktree create --name hidden-setup --setup inherit --json
```

`--agent` launches the selected agent in the first terminal. `--prompt` sends initial work to that agent. `--setup run|skip|inherit` controls repo setup hooks; `inherit` follows the repo policy.

## Terminals

```bash
alfred terminal list --worktree active --json
alfred terminal show --terminal <handle> --json
alfred terminal read --terminal <handle> --json
alfred terminal read --terminal <handle> --screen --json
alfred terminal read --terminal <handle> --cursor <cursor> --limit 1000 --json
alfred terminal send --terminal <handle> --text "continue" --enter --json
alfred terminal wait --terminal <handle> --for tui-idle --timeout-ms 300000 --json
alfred terminal create --worktree active --title "tests" --command "npm test" --json
alfred terminal split --terminal <handle> --direction horizontal --command "npm run dev" --json
alfred terminal rename --terminal <handle> --title "runner" --json
alfred terminal switch --terminal <handle> --json
alfred terminal close --terminal <handle> --json
alfred terminal close --worktree active --all --json
```

Omit `--terminal` to target the active terminal in the current worktree. Read before sending when you are not sure what the terminal is waiting for.

Close stops the process as part of removing the terminal. Use `--terminal <handle>` for one
terminal, or `--worktree <selector> --all` to durably close every terminal in exactly that
workspace, including its saved layouts and agent-resume records. Use workspace Sleep when those
terminals should resume later. If the execution host cannot confirm that every PTY stopped, bulk
close returns a failing `unverifiable` result rather than claiming the processes exited.
`terminal stop` remains only for compatibility with older tooling.

<Callout title="Terminal handles">
  Terminal handles are runtime-scoped. If Alfred restarts or a command reports a stale terminal
  handle, run `alfred terminal list --json` and reacquire the handle.
</Callout>

`terminal list` reports each terminal's `executionHostId` when Alfred can verify it, plus a result-level `hostScope` with covered and omitted host IDs. Treat a missing host identity or scope as **unverifiable**, not local. A missing terminal is evidence that it exited only when its execution host is listed in `hostScope.hostIds`.

By default, `terminal read` returns the accumulated output stream with terminal escapes stripped. Programs that redraw lines can therefore appear as stacked fragments. Use `--screen` when you need the currently rendered frame; the response's `source` identifies `stream`, `screen`, or `screen-unavailable`. Screen reads have no history to page, so `--screen` and `--cursor` are mutually exclusive.

For long output, use cursor reads. Save `nextCursor` from one stream read, then pass it back with `--cursor` to fetch only new output.

## Files

```bash
alfred file open src/App.tsx --worktree active --json
alfred file diff src/App.tsx --staged --worktree active --json
alfred file open-changed --mode both --worktree active --json
```

Paths are relative to the selected worktree. `open-changed` reads git status and opens changed files in edit, diff, or both modes.

## Built-in browser

Browser commands control Alfred's embedded browser tab for the selected worktree. They do not control Chrome, Safari, or the Alfred desktop UI.

Use a snapshot -> act -> snapshot loop:

```bash
alfred goto --url http://localhost:3000 --worktree active --json
alfred snapshot --worktree active --json
alfred click --element @e3 --worktree active --json
alfred fill --element @e1 --value "user@example.com" --worktree active --json
alfred wait --text "Welcome" --worktree active --json
alfred screenshot --worktree active --json
```

Refs such as `@e3` come from `snapshot`. Re-snapshot after navigation, tab switches, clicks that change the page, and any stale-ref error.

Tab and capture commands:

```bash
alfred tab list --worktree active --json
alfred tab create --url http://localhost:3000 --worktree active --json
alfred tab switch --index 1 --worktree active --json
alfred capture start --worktree active --json
alfred console --limit 50 --worktree active --json
alfred network --limit 50 --worktree active --json
alfred full-screenshot --worktree active --json
alfred pdf --worktree active --json
```

Use `alfred exec --command "<agent-browser command>" --json` only for browser actions that do not have a typed Alfred command yet.

Browser device emulation:

```bash
alfred set device --name "iPhone 12" --worktree active --json
alfred screenshot --worktree active --json
```

## Desktop computer use

Use `alfred computer` for native desktop apps outside the built-in browser:

```bash
alfred computer permissions --json
alfred computer list-apps --json
alfred computer get-app-state --app com.apple.Safari --json
alfred computer click --app com.apple.Safari --element-index 12 --json
alfred computer paste-text --app com.apple.Safari --text "hello" --json
```

See [Computer use](/docs/cli/computer-use) for the full workflow and permission setup.

## Mobile emulator

The mobile emulator commands control iOS Simulator devices through Alfred's worktree-scoped bridge. Use them instead of raw `serve-sim` or `simctl` when an agent is operating from inside Alfred, so lifecycle and active-device state stay attached to the current worktree.

```bash
alfred emulator list --worktree active --json
alfred emulator attach "<device-name-or-udid>" --worktree active --json
alfred emulator tap 0.5 0.7 --worktree active --json
alfred emulator type "hello" --worktree active --json
alfred emulator gesture '[{"type":"begin","x":0.5,"y":0.8},{"type":"move","x":0.5,"y":0.4},{"type":"end","x":0.5,"y":0.2}]' --worktree active --json
alfred emulator button home --worktree active --json
alfred emulator rotate landscape_left --worktree active --json
alfred emulator exec --command "tap 0.5 0.7" --worktree active --json
alfred emulator kill --worktree active --json
alfred emulator shutdown --worktree active --json
```

Coordinates are normalized from `0` to `1`. Prefer `tap` for single taps, and use `gesture` for drags or multi-step touch input. Pass `--device <udid-or-name>` or `--emulator <id>` when a script must target a specific simulator instead of the worktree's active emulator.

## Linear

The `alfred linear` surface is what agents use via the `alfred-linear` skill (legacy install name `linear-tickets` still works). Prefer `--json`. Linked worktrees resolve with `--current`.

### Read

```bash
alfred linear issue --current --full --json
alfred linear issue ENG-123 --comments --children --relations --activity --json
alfred linear search "auth bug" --workspace all --json
alfred linear list --filter assigned --limit 10 --json
alfred linear list-issues --team ENG --state started --assignee me --json
alfred linear list-issues --query auth --updated-at -P7D --cursor <cursor> --workspace <id> --json
alfred linear team list --json
alfred linear team states --team ENG --json
alfred linear team labels --team ENG --json
alfred linear project list --query launch --json
```

`--full` expands comments, children, attachments, relations, and activity. Section flags (`--comments`, `--children`, `--attachments`, `--relations`, `--activity`) work individually.

### MCP-style write

```bash
# Create or update (omit id/--current to create; requires --team and --title on create)
alfred linear save-issue --team ENG --title "Fix auth" --priority high --json
alfred linear save-issue ENG-123 --state "In Progress" --assignee me --json
alfred linear save-issue --current --project null --due-date null --json

alfred linear relation add ENG-1 --related ENG-2 --type blocks --json
alfred linear relation remove ENG-1 --related ENG-2 --type related --json
```

`save-issue` labels **replace** the full label set (Linear MCP `save_issue` semantics). Literal `null` clears assignee, estimate, due date, project, or parent.

### Field helpers (still valid)

```bash
alfred linear status set --current --to "In Progress" --json
alfred linear assignee set --current --me --json
alfred linear priority set ENG-123 --to high --json
alfred linear estimate set --current --to 3 --json
alfred linear due-date set --current --to 2026-08-01 --json
alfred linear label add --current --label backend --json
alfred linear comment add --current --body "Investigating regression" --json
alfred linear attach --current --url https://example.com/repro --title "Repro" --json
alfred linear create --title "Flaky login test" --team ENG --priority high --json
```

Run `alfred linear --help` or `alfred skills get alfred-linear` for the version-matched list. Pass an explicit issue id (e.g. `ENG-123`) when a script may run outside an Alfred-linked worktree.

## Skills (local, no runtime required)

List bundled guides, print a version-matched guide, or install/update hybrid skill packages without the desktop Settings UI:

```bash
alfred skills list
alfred skills get alfred-cli
alfred skills get orchestration --references
alfred skills get orchestration --reference recovery-and-cleanup
alfred skills get orchestration --full
alfred skills install --skill alfred-cli --skill orchestration
alfred skills install --all --dry-run
alfred skills update --all
```

`install` / `update` shell out to the same `npx skills` commands Settings uses. They do not contact the Alfred runtime. See [Alfred skills](/docs/cli/skills#keep-skills-up-to-date).

## Account (host-local runtime)

On a headless host running Alfred (`alfred serve` or the desktop app), add managed Claude/Codex accounts when the remote client cannot use **Add account** (remote runtime scope disables that button):

```bash
alfred account list
alfred account add                 # Claude by default
alfred account add --agent codex
```

`account add` runs `claude login` / `codex login` in **this** terminal on the host, then registers the captured credentials with the local runtime. Codex uses device authorization so the browser can finish on another machine. Run these on the machine that owns the accounts — not through a client-only remote session.

## Artifacts

Publish HTML or Markdown through the signed-in Alfred account. Viewing a public link does not require sign-in; create/list/update/delete do. **Publishing is off by default** — a human must enable **Settings → Artifacts → Allow publishing public artifact links** on the device. There is no CLI flag that grants the gate. `list`, `unshare`, and `delete` stay available so you can audit or revoke links after turning publishing off.

```bash
alfred artifacts share ./report.html --json
alfred artifacts share ./notes.md --json
alfred artifacts update ./notes.md --json
alfred artifacts unshare ./notes.md --json
alfred artifacts list --json
alfred artifacts list --cursor <cursor> --json
alfred artifacts delete <id> --json
```

- Accepted files: `.html`, `.htm`, `.md`, `.markdown`.
- `share` stores the edit token in the active Alfred profile and does not print it. `update` / `unshare` resolve by the same local path and profile that originally shared the file.
- `list` is paged (`nextCursor` → `--cursor`). `delete` takes the artifact id from `list` and does not need the original file.
- Relative HTML assets are not uploaded — share self-contained HTML or absolute asset URLs.
- Denied publish/update fails with `artifact_sharing_disabled`; fix Settings instead of retrying.
- Desktop: open a local HTML or Markdown file and use **Share as artifact**, or manage links from the sidebar **Artifacts** page.

## Automations, environments, and hooks

Scheduled prompts:

```bash
alfred automations list --json
alfred automations create --name "Daily review" --trigger daily --time 09:00 --prompt "Review open changes" --provider codex --repo id:<repoId> --disabled --json
alfred automations run <automationId> --json
```

Remote runtime environments:

```bash
alfred environment add --name work-laptop --pairing-code "alfred://pair?code=..." --json
alfred environment list --json
alfred environment rm --environment <selector> --json
```

Agent status hooks:

```bash
alfred agent hooks status --json
alfred agent hooks on --json
alfred agent hooks off --json
```

## Agent habits

- Prefer `--json` for automation and agent calls.
- Prefer selectors over parsing UI labels.
- Read terminal state before sending input unless the next input is obvious.
- Use worktree comments for progress checkpoints. See [Worktree checkpoints](/docs/cli/worktree-checkpoints).
- Use [Orchestration](/docs/cli/orchestration) for tracked multi-agent dispatches instead of ad hoc terminal prompts.
